# DnD Telegram Bot

Telegram-бот для DnD-кампании: персонажи, уровни по XP, бонус владения, монеты, инвентарь, магазин, предметы с картинками, передачи между игроками, квесты и рандомный лут.

Проект сделан как стартовая база, которую можно залить на GitHub, запустить локально или развернуть на VDS через Docker Compose.

---

## Что умеет бот

### Для игрока

- вход по логину и паролю, которые выдал администратор;
- просмотр профиля персонажа;
- просмотр уровня, XP, бонуса владения и монет;
- просмотр инвентаря;
- просмотр магазина по категориям;
- магазин открывается сразу в первой доступной категории;
- переключение между категориями магазина кнопками;
- пагинация магазина: одновременно показывается максимум 10 предметов;
- покупка предметов за монеты;
- в магазине видны только предметы, которые сейчас можно купить;
- продажа предметов из инвентаря;
- передача монет другим игрокам;
- передача предметов другим игрокам;
- просмотр карточки предмета с описанием, категорией, ценой, редкостью, картинкой и остатком в магазине.
- просмотр карточки текущей сессии: следующая игра, цель, краткий итог и важная заметка;
- вдохновение с самостоятельным использованием;
- состояния персонажа в профиле;
- броски кубиков через `/r d20+5`, `/r 2d6+3`, `/r adv+4` и `/r dis+2`;
- участие в лёгком трекере инициативы одним нажатием;
- автоматическое восстановление HP лечебными расходниками.

### Для администратора / мастера

- создание персонажа;
- выдача игроку логина и пароля;
- добавление или списание XP;
- добавление или списание монет;
- создание предметов магазина с категориями;
- создание новых категорий предметов через админ-панель;
- автоматическое распределение старых предметов по категориям одной кнопкой;
- выбор пользовательских категорий при создании и редактировании предметов;
- просмотр всех предметов в админке по страницам, максимум 10 предметов за раз;
- создание предметов только для выдачи игрокам, без продажи в магазине;
- добавление и изменение названия, описания/свойств, категории, цены, редкости и картинки предмета;
- установка лимита/остатка предмета в магазине;
- удаление предметов через админ-панель;
- скрытие и возврат предмета в магазин;
- настройка шанса выпадения предмета в рандомном луте;
- выдача предметов персонажу вручную;
- создание квестов с описанием и наградами;
- выдача награды за квест выбранным персонажам одной кнопкой;
- автоматическое деление XP, монет и предметных наград между выбранными персонажами с округлением вверх;
- выдача рандомного лута выбранному персонажу одной кнопкой;
- просмотр списка персонажей;
- просмотр списка предметов без зависания за счёт пагинации.
- заполнение карточки сессии и рассылка её игрокам;
- выдача вдохновения и управление состояниями персонажей;
- сводка HP, состояний, вдохновения и перегруза всей группы;
- запуск, переключение ходов и завершение инициативы;
- настройка фиксированного лечения HP у расходников;
- сгруппированная админ-панель и встроенная проверка целостности базы.

## Быстрый старт локально

### 1. Создай бота в Telegram

1. Открой `@BotFather`.
2. Выполни команду `/newbot`.
3. Получи токен бота.

### 2. Узнай свой Telegram ID

Можно использовать бота `@userinfobot`.

Telegram ID нужен, чтобы дать себе права администратора.

### 3. Скопируй `.env.example`

```bash
cp .env.example .env
```

На Windows можно просто скопировать файл `.env.example` и переименовать копию в `.env`.

### 4. Заполни `.env`

```env
BOT_TOKEN=твой_токен_бота
TELEGRAM_ADMIN_IDS=твой_telegram_id
DATABASE_PATH=./data/dnd_bot.sqlite3
CAMPAIGN_NAME=Моя DnD кампания
```

Если администраторов несколько:

```env
TELEGRAM_ADMIN_IDS=telegram_id_1,telegram_id_2
```

### 5. Создай виртуальное окружение

```bash
python -m venv .venv
```

Активировать на Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Активировать на Linux/macOS:

```bash
source .venv/bin/activate
```

### 6. Установи зависимости

```bash
pip install -r requirements.txt
```

### 7. Запусти бота

```bash
python -m app.main
```

## Развёртывание на VDS

### 1. Установи Docker и Docker Compose

Для Ubuntu/Debian обычно достаточно:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-plugin git
sudo systemctl enable docker
sudo systemctl start docker
```

### 2. Склонируй репозиторий

```bash
git clone https://github.com/USERNAME/dnd-telegram-bot.git
cd dnd-telegram-bot
```

### 3. Создай `.env`

```bash
cp .env.example .env
nano .env
```

Заполни:

```env
BOT_TOKEN=твой_токен_бота
TELEGRAM_ADMIN_IDS=твой_telegram_id
DATABASE_PATH=/app/data/dnd_bot.sqlite3
CAMPAIGN_NAME=Моя DnD кампания
```

### 4. Запусти контейнер

```bash
docker compose up -d --build
```

### 5. Проверь логи

```bash
docker compose logs -f
```

Если всё хорошо, в логах будет сообщение:

```text
Bot started in long polling mode
```

## Как пользоваться

### Первый вход администратора

1. Открой своего Telegram-бота.
2. Напиши `/start`.
3. Нажми `Админ-панель` или напиши `/admin`.

Кнопка админ-панели появится только у пользователей, чей Telegram ID указан в `.env`.

---

## Основной сценарий мастера

### 1. Создать персонажа

Админ-панель → `Создать персонажа`

Бот попросит:

1. логин;
2. пароль;
3. имя персонажа.

После создания бот покажет логин и пароль. Их нужно передать игроку.

Пароль в базе хранится не открытым текстом, а в виде хэша.

### 2. Игрок входит в персонажа

Игрок пишет:

```text
/login
```

Дальше вводит логин и пароль.

После входа Telegram-аккаунт игрока привязывается к персонажу.

### 3. Распределить старые предметы по категориям

Админ-панель → `Категории` → `Распределить предметы`

Бот пройдётся по уже созданным предметам и назначит категории по названию и описанию.
Например: кольца и амулеты попадут в аксессуары, болты и зелья — в расходники, верёвка и палатка — в снаряжение.

### 4. Создать предмет

Админ-панель → `Создать предмет`

Бот попросит:

1. название;
2. описание / свойства;
3. категорию;
4. цену покупки/продажи;
5. редкость;
6. шанс выпадения в рандомном луте от 0 до 100;
7. доступность: добавить в магазин или оставить только для выдачи игрокам;
8. остаток в магазине, если предмет добавляется в магазин;
9. картинку.

Для остатка можно указать:

```text
-1 — без лимита
0  — временно нет в наличии
5  — можно купить только 5 штук
```

Если предмет создан как `только для выдачи`, игрок не увидит его в магазине и не сможет купить. Администратор сможет выдать его вручную, а игрок сможет продать его из инвентаря.

Картинку нужно отправить как обычное фото в Telegram. Бот сохранит `file_id` картинки, поэтому сам файл отдельно хранить не нужно.

### 4. Выдать опыт или монеты

Админ-панель → `Добавить XP` или `Добавить монеты`

Можно вводить положительное или отрицательное число.

Примеры:

```text
50
```

```text
-10
```

### 5. Уровни и XP

Уровень персонажа считается автоматически по количеству XP. Отдельно хранить уровень в базе не нужно: админ добавляет или списывает XP, а бот сам показывает текущий уровень.

Используется таблица DnD 5e:

```text
1  — 0 XP      | бонус владения +2
2  — 300 XP    | бонус владения +2
3  — 900 XP    | бонус владения +2
4  — 2700 XP   | бонус владения +2
5  — 6500 XP   | бонус владения +3
6  — 14000 XP  | бонус владения +3
7  — 23000 XP  | бонус владения +3
8  — 34000 XP  | бонус владения +3
9  — 48000 XP  | бонус владения +4
10 — 64000 XP  | бонус владения +4
11 — 85000 XP  | бонус владения +4
12 — 100000 XP | бонус владения +4
13 — 120000 XP | бонус владения +5
14 — 140000 XP | бонус владения +5
15 — 165000 XP | бонус владения +5
16 — 195000 XP | бонус владения +5
17 — 225000 XP | бонус владения +6
18 — 265000 XP | бонус владения +6
19 — 305000 XP | бонус владения +6
20 — 355000 XP | бонус владения +6
```

Игрок может посмотреть таблицу командой:

```text
/levels
```

Также таблица доступна из главного меню через кнопку `Уровни`.

### 6. Выдать предмет вручную

Админ-панель → `Выдать предмет`

Можно выдать предмет игроку или забрать предмет отрицательным количеством. Выдавать можно любые предметы: и магазинные, и скрытые от магазина.

### 7. Изменить остаток предмета в магазине

Админ-панель → `Все предметы` → выбрать предмет → `Изменить остаток`

Можно поставить ограниченный остаток, `0` для отсутствия в магазине или `-1` для бесконечного количества.

### 8. Скрыть или вернуть предмет в магазин

Админ-панель → `Все предметы` → выбрать предмет → `Скрыть из магазина` или `Добавить в магазин`


### 9. Настроить шанс рандомного лута

Админ-панель → `Все предметы` → выбрать предмет → `Изменить шанс лута`

Примеры:

```text
0   — предмет не участвует в рандомном луте
25  — шанс выпадения 25%
100 — предмет выпадет всегда при броске лута
```

Рандомный лут работает как таблица выпадения: бот проверяет все предметы, у которых шанс больше 0%, и выдаёт персонажу те предметы, которые прошли проверку.

### 10. Создать квест

Админ-панель → `Квесты` → `Создать квест`

Бот попросит:

1. название квеста;
2. описание;
3. общий XP;
4. общую награду в монетах;
5. предметную награду или вариант `Без предмета`;
6. общее количество предметов, если выбран предмет.

При выдаче награды бот делит общий XP, монеты и предметы между выбранными персонажами. Если награда делится не ровно, бот округляет награду в большую сторону.

Пример: квест даёт `100` монет на `3` игроков. Каждый получит `34` монеты.

### 11. Выдать награду за квест

Админ-панель → `Квесты` → `Список квестов` → выбрать квест → `Выдать награду`

Дальше выбери нужных персонажей галочками и нажми `Выдать выбранным`.

### 12. Выдать рандомный лут

Админ-панель → `Рандомный лут` → выбрать персонажа → `Кинуть рандомный лут`

Бот одной кнопкой проверит шансы всех предметов из таблицы лута и добавит выпавшие предметы в инвентарь персонажа.

### 13. Передать монеты или предмет игроку

Игрок может открыть `Главное меню` → `Передать` или использовать команду:

```text
/transfer
```

Дальше можно выбрать:

- передать монеты;
- передать предмет из инвентаря.

Передача работает только между уже созданными персонажами.

## База данных

Бот сам создаёт SQLite-базу при первом запуске.

По умолчанию база хранится здесь:

```text
./data/dnd_bot.sqlite3
```

В Docker база хранится в volume-папке проекта:

```text
./data
```

Эта папка добавлена в `.gitignore`, чтобы случайно не залить базу с данными игроков на GitHub.

## Таблицы

### `characters`

Хранит персонажей:

- логин;
- хэш пароля;
- Telegram ID игрока;
- имя персонажа;
- XP;
- автоматически рассчитанный уровень по XP;
- бонус владения по уровню;
- монеты.

### `shop_items`

Хранит предметы:

- название;
- описание;
- цену;
- редкость;
- Telegram `file_id` картинки;
- активность предмета в магазине;
- остаток в магазине: `-1` без лимита, `0` закончился, положительное число — лимит;
- шанс выпадения в рандомном луте.

### `inventory`

Хранит связь персонажей и предметов:

- какой персонаж;
- какой предмет;
- количество.

### `quests`

Хранит квесты:

- название;
- описание;
- общий XP;
- общие монеты;
- предметную награду;
- активность квеста.

### `transactions`

Хранит историю операций:

- выдача XP;
- выдача монет;
- выдача предметов;
- покупка предметов;
- продажа предметов;
- передачи монет между игроками;
- передачи предметов между игроками;
- выдача наград за квесты;
- выдача рандомного лута.

### Помощник мастера

- `character_conditions` хранит короткие состояния персонажей;
- `initiative_encounters` и `initiative_entries` хранят только порядок текущего боя;
- карточка сессии хранится в `game_sessions`;
- вдохновение и бонус инициативы хранятся у персонажа;
- `heal_hp` у предмета задаёт фиксированное лечение при использовании.

Визуальные правила для следующих изображений предметов сохранены в `ASSET_STYLE.md`.

### Расширение магазина

В магазин встроен дополнительный набор из 21 предмета: простое оружие, инструменты,
походные расходники, снаряжение и редкие сюжетные вещи. У каждой позиции есть
описание эффекта, вес, цена покупки, цена продажи в размере 80% и локальная картинка
в `assets/items/`.

Лечебная мазь восстанавливает 6 HP. Для старых зелий лечения автоматически заданы
значения 8, 18 и 36 HP для малого, среднего и большого зелья соответственно.
Старые предметы `Арбалет`, `Лук "Грамдаля"`, `Кирка` и `Набор целителя`
автоматически получают правильную категорию при запуске.

## Важные замечания по безопасности

1. Никогда не пушь `.env` на GitHub.
2. Никогда не публикуй токен Telegram-бота.
3. Не добавляй файл базы данных в репозиторий.
4. Если токен случайно попал в GitHub — сразу перевыпусти токен через `@BotFather`.
5. Пароли игроков хранятся в виде хэша, но всё равно лучше не использовать настоящие личные пароли.

## Автоматические проверки

Проект использует встроенный `unittest`, поэтому отдельные тестовые зависимости не нужны.

Запуск всех тестов:

```bash
python -m unittest discover -s tests -v
```

Тесты работают только с временными SQLite-базами. Файл из `DATABASE_PATH` не используется.
Сборка Docker также запускает все тесты и останавливается, если хотя бы один тест не прошёл.

Проверяются:

- создание и обновление схемы SQLite;
- целостность базы и внешних ключей;
- хэширование паролей и ограничение попыток входа;
- атомарные покупки, продажи и передачи;
- инвентарь, расходники, экипировка и переносимый вес;
- квестовые награды без повторной выдачи;
- короткий отдых и журнал персонажа;
- наличие проверки администратора во всех административных маршрутах;
- контейнерный healthcheck.

SQLite запускается в режиме WAL с таймаутом ожидания блокировок. Критические операции
начинают транзакцию `BEGIN IMMEDIATE`, поэтому одновременные нажатия не могут списать
монеты или предметы дважды из одного и того же остатка.
- броски кубиков `/roll 1d20+3`;
- отдельная цена покупки и цена продажи;
- подтверждение продажи дорогих предметов.

## Импорт персонажей Long Story Short

Импортёр читает имя вида `Солар(Олег 4)`: создаёт персонажа `Солар`, игрока `Олег`,
сессию `Сессия 4` и отдельные разделы листа. Повторный запуск обновляет того же
персонажа и не создаёт дубликат.

```bash
python -m app.import_lss_character "/app/data/imports/character.json" --password 12345
```

Экспорт Long Story Short содержит только ID заклинаний. Если рядом подготовлен
каталог с полями `id`, `name`, `description` и `level`, его можно передать через
`--spell-catalog`; иначе бот сохраняет ID и честно отмечает отсутствие описания.
